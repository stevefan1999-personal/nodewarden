# NodeWarden agent notes

Bitwarden-compatible Cloudflare Worker. See `ARCHITECTURE.md` and `docs/`.

## Conventions

- Schema lives in `src/db/schema.ts` (+ `relations.ts`). `npm run db:generate` (drizzle-kit) writes each change as a new `migrations/<id>/migration.sql`; data-only fixes are `npx drizzle-kit generate --custom --name <slug>` with the SQL written by hand. Never edit an applied migration. Wrangler applies pending migrations (`migrations_pattern` in both wrangler configs) before every `deploy` and `dev`, and records them in `d1_migrations`; the Worker never runs DDL. Tests and tooling build their databases from the same files (`MIGRATIONS` in `src/test/support/d1-sqlite.ts`).
- D1: `db.batch()` only; never `db.transaction()`. A statement binds at most 100 parameters: chunk id lists with `statementChunks(items, statement)` (`src/db/client.ts`), which renders the statement to measure what it binds, and never hand-count (NULLs in `.set()`, JSON paths and helper literals all bind). Multi-row inserts use `chunkRows(rows, columnCount(table))`.
- No raw SQL: every query and statement is a drizzle builder through `getOrm(db)` (Durable Object SQLite through `drizzle-orm/durable-sqlite`), batched with `getOrm(db).batch([...])`; use `abortUnlessChanged` (`src/db/client.ts`) for a batch that must roll back when a guarded write changed nothing. Hand-written SQL exists only in `src/db/sql.ts` as typed helpers (`coalesce`, `jsonExtract`, `excluded`, `likeEscaped`, `jsonValues`, ...); importing `sql` anywhere else, `env.DB.prepare/exec/batch`, `storage.sql.exec`, and strings or SQL values handed to drizzle `run/all/get/values` are lint errors, in tests and tooling too. Reading `prepare`/`exec` as a value (`env.DB.prepare.bind(...)`) counts too. The only exception is a disable with a concrete reason: migration execution in tooling (`scripts/support/sm-d1-batch.ts`, which migrates a Miniflare D1). Tests never touch `env.DB` directly: `wrapStatements` and `interceptStatement` (`src/test/support/env.ts`) observe, fail or race the statements drizzle prepares, and `abortWrites` makes a write fail inside a batch, all through the SQLite-backed D1 stand-in (`src/test/support/d1-sqlite.ts`), which is the tests' SQL driver.
- `npm run lint` must pass before committing. It type-checks tests and tooling (`tsconfig.eslint.json`, Workers types plus Node) and the Playwright specs (`e2e/tsconfig.json`, DOM types for their page callbacks), includes Prettier (`npm run format` fixes drift; html/css tagged templates are served output and stay unformatted), and besides the raw-SQL rule it forbids unused variables and expressions and any module-local function referenced from only one place: inline such a function at its call site (exported functions are the module API and exempt).
- Auth engine is Better Auth (`src/auth.ts`). Bitwarden `/identity` and `/api` stay adapters. Sessions live in `session`, credentials in `account`. Access JWTs stay HS256 via `JWT_SECRET`. Do not add `withCloudflare()` (drizzle 1.0-rc type clash).
- Personal vault queries and mutations must exclude `organization_id IS NOT NULL`. Org cipher access goes through `src/handlers/cipher-access.ts`.
- Do not store plaintext vault or SM values.
- Official Bitwarden clients are the API contract; Vaultwarden is the AGPL reference.
- The only web vault is the official Bitwarden web built from `official-web/`. The Worker ships it as static assets on the same origin as the API and the connector pages, so passkeys and security keys share one relying-party ID; never split the vault onto another hostname. `run_worker_first` in both wrangler configs sends the backend paths, `/admin` and our own `public/*.html` pages to the Worker; Cloudflare serves every other file directly with the headers `scripts/build-worker-assets.mjs` writes. `WEB_VAULT_ORIGINS` names the Worker origin.
- Official web signup uses `/identity/accounts/register/send-verification-email` + `/finish`. Send a Cloudflare Email (`EMAIL` binding + `EMAIL_FROM`) and return an empty JSON string (never an inline JWT). Official self-host web still continues to the password form; the emailed `/redirect-connector.html#finish-signup` link carries the token when the user opens it.
- The patched web vault creates orgs by name via `POST /api/organizations`, preserving client-generated encrypted keys. Unmodified self-host web uses `POST /organizations/licenses/self-hosted` (any JSON); keep `GET /api/licenses/nodewarden-enterprise.json` for it. Emergency access lives in `emergency_access`.
- Prefer Cloudflare D1 / KV / DO / Queues / Workflows / R2 over new in-process state.
- Log a caught error only through `withoutQueryParams` (`src/db/client.ts`; lint rule `nodewarden/no-raw-error-log`): a drizzle failure carries every bound value in its message and stack, even after crossing a Durable Object call. Never log tokens, codes, invite codes, upstream reply bodies or request URLs. Official clients put credentials in query strings (attachment and Send download tokens, SSO codes), so Workers invocation logs stay off, or are scrubbed, before observability is enabled.
- Instance backups stream through the `BACKUPS` R2 bucket (`src/services/backup-zip.ts`): never buffer a whole archive, a whole table set beyond the export snapshot, or a file in memory.
- A new schema table goes into `BACKUP_TABLES` (`src/services/backup-archive.ts`) after every table it references, or into `INSTANCE_LOCAL_TABLES` in `backup-archive.test.ts` with its reason (runtime authentication state, rate limits, the administrator log); the tests fail until it is on one side. Give rows from older archives a value for a new required column in the restore's prepared payload.
- Attachments upload through the Worker: official clients PUT each file to the URL NodeWarden returns with `fileUploadType` 1, the way they upload to Azure, up to the 100 MiB limit. They ignore any URL for the Direct type, so a presigned R2 URL can never serve them.
- Tests: `npm test` builds the admin portal, then runs `src/**/*.test.{ts,mjs}`. Unit tests sit next to their module; route tests that drive the real Worker `fetch` live in `src/test/` and use `src/test/support/env.ts` (`createTestEnv`, `seedUser`, `authedFetch`) on a SQLite-backed D1 that enforces the 100-parameter cap and batch atomicity. `npx tsc --noEmit` checks the Worker alone, against the Workers types for its compatibility date; `scripts/` holds only build, deploy and e2e tooling.
- Routing is a Hono 4 app (`src/router.ts` + `src/router-*.ts`). Handlers keep their `(request, env, …)` signatures and routes call them with `c.req.raw`. Paths match exact case except the Secrets Manager sub-router, which lower-cases its path.
- Repositories (`src/services/storage-*-repo.ts`) are called directly with `env.DB`; there is no storage facade. `shared/backend-paths.ts` is the single list of backend paths, used by `run_worker_first` and the Worker's asset-versus-app decision; `src/test/backend-paths.test.ts` fails when a route or either wrangler config drifts from it.
- Validate input with zod, never hand-rolled typeof chains: request bodies through `parseBody(request, Schema)` (`src/utils/response.ts`, PascalCase keys normalized to camelCase), Worker variables through `readEnvConfig(env)` (`src/config/env.ts`), stored JSON through schemas with `.catch` fallbacks. Keep user-facing error messages stable; tests pin them.
- Prefer installed packages over hand-rolled helpers: `hono/jwt`, `hono/utils/encode`, `hono/utils/crypto`, `hono/utils/cookie`, `hono/cors`, `hono/html`, `hono/utils/ipaddr`, `aws4fetch`, `otpauth`; hex through `Uint8Array#toHex` / `Uint8Array.fromHex`. Constant-time comparisons use `constantTimeEquals` (`src/utils/api-key.ts`). Construct `new RateLimitService(env)`; per-minute budgets need a matching `[[ratelimits]]` binding in both wrangler configs.
- Parallel agent worktrees share `refs/stash`; never use `git stash` there (the user keeps a stash of their own).

- SM authorization goes through `src/services/sm-authz.ts` + `smContext`; no ad-hoc checks.

- Machine JWTs carry `type=ServiceAccount`; only `router-sm`'s machine allowlist accepts them.

- SM access = confirmed member, independent of licenses. Owners/Admins have full access; other members use object policies.

- All transactional mail goes through `sendMail` and data-only templates. Links use configured vault origins or the Worker request origin, never `X-Forwarded-Host`.
- Portal admins come from `ADMIN_EMAILS`, independently of `users.role`. The portal is the SvelteKit app in `admin/`, rendered on the server only (no client JavaScript, `PORTAL_HEADERS` CSP) and embedded in the Worker by `src/admin/portal.ts`. Its pages reach Worker services only through `platform.portal` (`src/admin/portal-contract.ts`, implemented in `src/services/admin-portal.ts`); never import Worker modules into `admin/`, because a second copy of a module splits state such as the user cache. Keep portal URLs and status codes stable, and run `npm run check:admin` (svelte-check) with lint and tests.

- With `ADMIN_EMAILS` configured, `users.role` is derived by `syncVaultAdminRoles` from verified addresses, with a no-lockout guard. Do not write roles outside the guarded bootstrap, sync, or backup-import paths. Account creation uses `createUser` (INSERT); `saveUser` only UPDATEs its explicit field list, defaulting to profile fields. Never write a whole stale account snapshot. Saves compare the original security stamp and return false on a lost update; credential writers must reject that result. Role, status, email verification, recovery codes and Email 2FA use targeted writers.

- Email codes go only through `src/services/email-otp.ts`: purpose/binding-scoped, hashed at rest, single-use, budgeted and five-minute expiry.

- Bitwarden event history is `events` via `recordEvents`/`recordUserEvent`/`recordSendEvent` in `src/services/events.ts`, called with the request after the committed write and only on real transitions; never store names, values or ciphertext. Reads go through `listEventsResponse` with an explicit authorized scope (`accessEventLogs` for organizations) and refuse with 404, never 403. Prune by receipt age only, never a shared row cap. `audit_logs` stays the separate administrator log.

- Email changes must atomically update the normalized email, verified flag, server hash, client-rewrapped key and credential mirror, rotate the stamp and revoke sessions. Better Auth `user.changeEmail` and `user.deleteUser` stay disabled; they bypass vault key and deletion invariants.
